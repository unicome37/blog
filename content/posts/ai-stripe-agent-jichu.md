最近连续看了几轮 Agent Commerce 的进展，觉得 Stripe 这家公司值得单独拿出来观察。

它现在做的事情，已经不太像一家传统意义上的支付公司。

过去 Stripe 的核心角色很好理解。

互联网公司做网站、卖软件、卖商品，需要收钱。

Stripe 帮它们接支付。

开发者接一个 API，就可以收信用卡、处理退款、订阅、发票。

所以 Stripe 过去最重要的位置，是：

**互联网商业的支付基础设施。**

但到了 Agent 时代，这个位置正在发生变化。

Agent 不只是帮用户找东西。

它开始替用户完成任务。

订酒店。

买商品。

支付账单。

发票。

退款。

转账。

管理现金。

一旦 AI 从“帮我找到”进入“帮我做”，支付就不再只是交易最后那一下。

它会逐渐变成：

**一个 Agent 是否真正拥有行动能力的分界线。**

而 Stripe 正在往这个位置走。

## 一、Agent 真正进入经济世界，绕不开“钱”

过去的 AI 很多时候停留在认知世界。

帮你写一封邮件。

总结一个文档。

查一份资料。

分析一家公司。

这些事情当然有价值，但它们还没有真正改变现实中的资源关系。

一旦 Agent 开始替人完成任务，问题马上变了。

帮我找到一张机票，不需要碰钱。

帮我把机票订好，就需要付款。

帮我分析订阅支出，不需要碰钱。

帮我取消订阅、支付账单、调度现金，就已经进入金融执行。

所以从 Agent 的演化来看，会有一条很清楚的路径：

**Find→ Do→ Delegate→ Pay→ Settle。**

越往后，Agent 越不像一个工具。

越像一个真正的代理人。

而支付，正是从“认知代理”进入“经济代理”的那道门。

## 二、Stripe 押注的不是某一个 Agent，而是所有 Agent 最后都要完成交易

这也是 Stripe 最有意思的地方。

它没有必要赌：

最后是 ChatGPT 赢。

还是 Claude 赢。

还是 Meta Muse、Instinct 或某个新的 Personal Agent 赢。

Stripe 可以站在这些产品下面。

因为无论前端 Agent 是谁，只要它开始替用户完成真实经济活动，就会碰到：

付款。

授权。

钱包。

发票。

退款。

转账。

结算。

风控。

账户。

所以 Stripe 押注的其实不是某个 AI 产品。

而是一个更底层的事实：

> **只要 Agent 开始行动，它就必须进入资源调用。**

这和当年 Visa、Mastercard 的位置有点像。

它们不需要拥有消费者入口。

只要大量交易最终经过它们，网络就有价值。

Stripe 现在想做的，很可能也是类似的事情：

**Personal Agent 可以有很多个，但经济执行层最好只有少数几个。**

## 三、Link 的变化尤其值得看

过去看 Link，很多人把它理解成 Stripe 的快速结账工具。

但到了 Agent 时代，它开始有另一层意义。

如果一个 Personal Agent 可以代表用户购物，但又不能直接拿到用户真实的信用卡信息，那么中间就需要一个受控的钱包层。

这个钱包要知道：

这是谁的钱。

这个 Agent 有没有权限。

允许在哪些商户使用。

能花多少钱。

什么时候失效。

用户能不能撤销。

这时候 Link 的角色就从：

**帮助用户更快付款**

变成：

**帮助 Agent 在用户授权下付款。**

差别很大。

前者是 Checkout。

后者开始接近：

**Agent Wallet。**

一旦这个位置成立，Stripe 掌握的就不只是支付凭证。

而是：

**用户允许 Agent 如何调用经济资源。**

这已经开始进入委托关系。

## 四、Stripe 最近越来越像是在搭一套“Agent 金融操作系统”

如果把最近 Stripe 的几个动作放在一起看，会更明显。

它有 Link for agents。

有 Shared Payment Tokens。

有 Agent Wallet。

有 Agentic Commerce Suite。

有 ACP。

有 MPP。

又开始把企业账户、Treasury、发票、退款、转账这些能力直接暴露给 Agent。

这些东西单独看都像产品功能。

但放在一起看，其实对应的是一套完整结构：

**Agent 身份**

**↓**

**权限**

**↓**

**支付凭证**

**↓**

**账户**

**↓**

**执行**

**↓**

**审批**

**↓**

**结果通知**

**↓**

**结算**

这已经不太像普通支付 API。

更接近：

> **一个让 Agent 在明确权限内管理经济活动的操作系统。**

尤其当 Stripe 开始支持：

小额操作自动执行，

大额操作人工批准，

执行成功或失败回传状态，

这件事的性质已经变了。

因为 Agent 最危险的问题从来不是：

“它会不会发起动作？”

而是：

**它能不能在正确边界里行动，并且让人知道最后到底发生了什么。**

## 五、这一点和 Instinct 的贝果事件正好相反

上个月看到一个很典型的例子。

用户让 AI 助理替孩子生日会订贝果。

信用卡扣款失败。

Agent 没有告诉用户。

等人到了店里，才发现订单根本没有成立。

真正的问题不是支付失败。

支付失败很正常。

真正的问题是：

**任务失败了，但系统没有把失败升级给人。**

这说明 Agent 真正进入现实世界以后，一个完整任务不能只是：

“我尝试过了。”

而必须是：

**发起→ 支付→ 商户确认→ 状态追踪→ 完成→ 异常通知。**

只有这样，用户才敢真正把事情交出去。

否则 AI 替你办完以后，你还得自己再确认一次。

那并没有真正节省多少心力。

所以 Stripe 最近在做的执行状态、审批、Webhook、结果通知，看起来很底层，实际上非常重要。

因为 Agent Commerce 最终竞争的不是：

谁最会发起交易。

而是：

> **谁能让交易可靠地完成。**

## 六、支付在 Agent 时代会被重新定义

过去我们很容易把支付理解成：

钱从 A 转到 B。

但从 Agent 的角度看，这个定义太浅了。

一个人买机票，是在配置自己的资源。

企业买原材料，也是在配置资源。

投资、保险、订阅、采购，本质都一样。

所以支付更深一层的意义是：

> **资源配置意图经过授权以后，被现实执行。**

于是完整过程应该是：

**资源存在→ 形成目标→ 作出判断→ 完成授权→ Agent 执行→ 支付发生→ 新的资源关系形成。**

这样看，Stripe 真正争夺的位置就不是“最后付款”。

而是：

**授权到执行之间的那层经济基础设施。**

## 七、这也是为什么 PAP、ACP、MPP 会同时出现

最近有一个很明显的现象：

Agent 世界开始出现各种协议。

PAP 解决：

**Personal Agent 如何代表用户与企业交互。**

ACP 解决：

**Agent 如何进入商业交易流程。**

MPP 解决：

**机器和 Agent 之间如何完成支付。**

MCP 解决：

**模型如何调用工具和外部系统。**

这些协议看起来很多。

但本质上是在给未来的 Agent 经济做分层。

可以简单理解成：

**MCP：我能调用什么工具。**

**PAP：我代表谁，企业允许我做什么。**

**ACP：商业交易怎样进行。**

**MPP / 支付网络：钱怎样真正过去。**

这和互联网早期的协议栈很像。

不是一个协议解决所有问题。

而是一层一层把复杂性抽象掉。

Stripe 最值得关注的地方在于：

它正在主动站在这些协议之间最接近经济价值的那一层。

因为无论上面用什么 Agent、什么协议，最后只要进入真实交易，就要解决钱。

## 八、所以 Stripe 的竞争对手也开始变了

以前看 Stripe，主要会想到：

PayPal。

Adyen。

Block。

传统支付收单机构。

但 Agent 时代，竞争边界开始扩展。

Visa、Mastercard 开始做 Agent 身份和可信支付。

Google 有自己的 Agent Commerce 和 Google Pay。

Shopify 有商户网络和 Shop Pay。

1Password 开始进入 Agent 凭证和身份层。

Skyfire、Forter 在做 Agent 身份和风险判断。

甚至一些 AI 平台自己也可能把支付、钱包和授权做进去。

所以 Stripe 真正的竞争，不再只是：

谁的支付费率更低。

而是：

> **谁能同时掌握身份、授权、支付、商户、风控和结算。**

这个位置一旦形成，护城河会比单纯支付处理深很多。

## 九、但我现在还不会下结论说 Stripe 已经赢了

这一点也很重要。

今天可以看到的是：

Stripe 的产品覆盖面越来越完整。

它进入了多个 Personal Agent。

开始提供钱包、支付、企业资金管理、审批和执行状态。

也参与 PAP 等协议设计。

这些都说明它占据了很好的位置。

但真正决定它能不能成为 Agent 时代“默认经济接口”的，不是产品数量。

而是几个更硬的指标：

Agent 支付金额到底有多少？

多少 Personal Agent 真正在生产环境里使用 Stripe？

多少商户默认接受 Agent 交易？

Agent 交易的成功率、退款率和欺诈率是多少？

Stripe 能不能因为 Agent 获得新的 take rate？

还是只是把原有支付量换了一个入口？

这些数据现在还远远不够。

所以现阶段更适合说：

**战略位置越来越清晰，利润兑现还在早期。**

## 十、真正值得关注的是 Stripe 能不能从“支付公司”变成“代理经济的账户层”

如果未来 Agent 越来越深入，事情还会继续变化。

Agent 不只会付款。

它还可能：

管理企业现金。

创建发票。

收款。

退款。

调拨资金。

管理预算。

调用信用。

甚至围绕目标持续配置资源。

到了这一步，Stripe 的位置就不再只是：

**Payment Infrastructure。**

而会开始接近：

**Economic Operating System for Agents。**

也就是：

Agent 经济的金融操作系统。

它不需要自己决定用户该买什么。

也不需要自己成为最聪明的 AI。

它只需要保证：

当 Agent 获得合法授权以后，

**钱能够安全、可靠、可追踪地动起来。**

## 十一、这和我们前面讨论的“从 Find 到 Do”正好接上

过去互联网帮人：

找到信息。

找到商品。

找到服务。

平台因此掌握流量。

Agent 开始替人：

完成任务。

平台因此开始掌握任务。

再往下一步，任务要真正完成，就必须调用：

时间。

资金。

信用。

现实服务。

这时候就会进入资源配置。

所以整条链可以写成：

**Find→ Do→ Delegate→ Pay→ Settle→ Verify。**

Personal Agent 负责前面几步。

Stripe 想占据后面几步。

这就是它最近这些动作真正值得关注的原因。

## 十二、Stripe 真正想成为的，也许不是“AI 支付公司”

如果只是 AI 支付，这个故事其实并没有多大。

支付公司支持新的消费入口，本来就是正常业务。

但如果 Stripe 最终能够做到：

无论用户使用哪个 Personal Agent，

无论企业使用哪套 Agent，

无论上面跑什么模型，

最后涉及经济资源的时候，

大家都通过 Stripe 完成：

身份确认。

授权。

钱包。

支付。

资金调拨。

结算。

退款。

结果通知。

那它的角色就完全不同。

它更像：

> **Agent 经济世界里的经济接口。**

过去互联网时代，Stripe 帮助一个网站第一次变成一家可以收钱的互联网公司。

未来 Agent 时代，它可能想做的是：

> **让一个 Agent 第一次真正成为可以参与经济活动的主体。**

这可能才是 Stripe 这一轮布局真正值得长期观察的地方。

不是它又多做了几个 AI 产品。

而是它正在尝试占据一个新的基础设施位置：

**当越来越多事情从“我自己做”变成“Agent 替我做”以后，谁来管理这些代理背后的钱、权限和责任。**

如果这个世界真的到来，Stripe 现在正在提前站进去。
