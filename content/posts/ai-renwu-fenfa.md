这两天跟踪到几件看起来并不完全相关的事情。

有人把最近很火的 Personal Agent Instinct 形容成“AI 版携程”。

10月6日，Sierra 和 Meta 又联合推出了 Personal Agent Protocol（简称"PAP"），希望建立一套开放标准，让个人 Agent 可以代表用户直接与企业的网站、API 或企业 Agent 打交道。参与这项工作的还有 Stripe、Shopify、Walmart、Instinct 等公司。

与此同时，Stripe 正在非常积极地进入 Agent Commerce。它不仅参与 PAP，此前还推出了 Agentic Commerce Protocol、Machine Payments Protocol、Shared Payment Tokens 和 Link 的 Agent Wallet。9 月底，Stripe 透露，通过 Link 完成的 Agent 购物在一个月里增长了 38 倍。

把这些事情放在一起看，会发现它们可能都指向同一个变化：

互联网正在从“流量分发”，走向“任务分发”。

过去平台最重要的权力，是决定用户看到什么。

未来 Agent 平台更重要的权力，可能是决定：

用户的一件事情，交给谁去完成。

这两种权力，看起来只差一步，实际上可能对应完全不同的商业世界。

## 一、过去二十年，互联网最值钱的是“把人送过去”

回头看传统互联网，它最核心的能力其实一直是：

帮我找到。

Google 帮我找到网页。

淘宝帮我找到商品。

携程帮我找到酒店和机票。

美团帮我找到餐厅和服务。

平台不断降低搜索成本、匹配成本和交易成本。

所以互联网形成了一套非常稳定的商业逻辑：

用户产生需求→ 平台聚合流量→ 平台把流量分给服务商→ 服务商为获得流量付费。

搜索广告如此。

电商佣金如此。

OTA 也是如此。

携程自己并不拥有大多数飞机和酒店，但它拥有大量旅行需求。当用户说“我要去东京”，平台把需求路由给航空公司、酒店、租车和其他服务商。

所以携程真正重要的资产，并不是酒店房间。

而是：

旅行需求的分配权。

互联网平台真正的核心资产，很多时候也并不是自己生产什么。

而是掌握：

谁得到用户。

## 二、Agent 时代，平台开始从“把人送过去”变成“把事情送过去”

Personal Agent 出现以后，这个关系开始发生变化。

用户以后可能不再说：

“帮我找三家东京的酒店。”

而是直接说：

下周去东京三天，预算一万元，还是按照以前的习惯安排。

这句话里面没有酒店网站。

没有航空公司。

甚至没有具体产品。

只有一个：

Intent——目标。

接下来 Agent 自己决定：

查什么。

找谁。

怎么比较。

走哪个接口。

用什么支付方式。

出现问题以后怎么办。

最终把事情完成。

所以传统互联网的结构是：

人 → 平台 → 信息 / 服务商。

Agent 时代开始变成：

目标 → Agent → 服务商 / 其他 Agent → 结果。

平台分发的不再只是流量。

而开始变成：

任务。

这可能是一个非常大的变化。

因为一个用户访问了哪家网站，和一个用户把“完成这件事情”的责任交给谁，经济价值完全不同。

## 三、所以“AI 版携程”这个比喻是对的，但还不够大

如果只看现在，Instinct 之类的 Personal Agent 确实很像“AI 版携程”。

它可以替用户联系服务商、购物、安排事情，然后在背后调用各种现成服务。

但携程只是：

旅行任务路由器。

未来 Personal Agent 想争夺的是：

个人全部可委托事务的任务路由权。

旅行。

购物。

家政。

保险。

金融。

医疗预约。

工作事务。

企业采购。

如果一个 Personal Agent 最终可以理解：

你到底想完成什么，

然后自动判断：

应该调用哪一个垂直 Agent、哪一个企业、哪一种服务，

那么它就不再是普通应用。

它开始成为：

General Task Router——通用任务路由器。

这个位置非常像过去的平台入口，但比流量入口更深。

过去的平台决定：

你先看见谁。

未来的 Agent 决定：

这件任务交给谁。

## 四、从“流量分发”走向“任务分发”，商业模式自然也会发生变化

这也是为什么最近有人提出：

AI 时代可能出现大量“零订阅、按结果付费”的产品。

我觉得方向是对的。

因为互联网时代用户购买的往往是：

商品，

软件，

信息，

或者工具使用权。

到了 Agent 时代，越来越多用户真正想购买的可能只是：

结果。

我并不想购买一套采购软件。

我想采购完成。

我并不想订阅一个退款管理工具。

我想把退款追回来。

我不一定想购买一个复杂旅行软件。

我只想周五晚上顺利住进那家合适的酒店。

所以商业模式自然会沿着一条路径继续向前：

Subscription→ Usage Fee→ Task Fee→ Success Fee→ Outcome Sharing。

最后卖的已经不再只是能力。

而是：

完成任务的责任。

## 五、Success Fee 最有意思的地方，是钱不一定由用户付

如果 Agent 完成一个任务以后收费，一个很自然的问题就是：

谁付这笔钱？

可能是委托人。

比如 Agent 帮我追回一万元退款，我支付追回金额的一部分。

也可能是服务提供方。

比如 Agent 替用户找到一家酒店并完成预订，酒店向 Agent 平台支付佣金。

还可能双方都支付。

这就和携程、美团、信用卡等双边市场非常接近。

于是 Agent 平台天然会形成一个新的多边商业结构：

用户提供任务。

服务商提供供给。

Agent 负责匹配、执行和验证。

平台从完成结果中获得收入。

从这个意义上说，Success Fee 可能就是 Agent 时代最容易看见的商业模式表象。

底下真正发生的是：

商业价值从“获得点击”转向“获得任务”。
## 六、但这里立即出现一个很重要的问题：Agent 究竟代表谁？

这可能是 Personal Agent 商业模式里非常深的一道矛盾。

如果我把一件事情交给自己的 Agent，我天然会认为：

它代表我。

但如果真正付钱的是酒店、保险公司或者商品卖家呢？

那么问题马上出现：

它推荐 A，是因为 A 最适合我，

还是因为 A 给它更高佣金？

传统互联网早就存在这个问题。

搜索结果和广告之间有利益冲突。

电商排名和推广费用之间有利益冲突。

但过去平台只是：

推荐。

用户还会自己决定。

Agent 时代则不同。

如果 Agent 已经获得行动权，它可能直接替用户：

选择。

下单。

支付。

这时候利益冲突的敏感度会高得多。

所以未来 Agent 商业模式里会出现一个非常重要的问题：

谁付钱，与 Agent 忠于谁，必须被区分开。

代理关系越深，商业利益越需要透明。

否则平台可能为了多赚一次佣金，损失用户多年建立起来的信任。

这在商业上可能是一笔非常不划算的交易。

因为 Personal Agent 最重要的资产，并不是某一次交易。

而是：

长期委托关系。

## 七、真正让“任务分发”成为产业，而不是几个 App 的，是协议开始出现

这也是为什么 Sierra 和 Meta 这次推出 Personal Agent Protocol 值得注意。

今天的 Personal Agent 很多时候仍然在模拟人：

打开网页。

点按钮。

填表格。

打客服电话。

效率并不高，而且非常容易失败。

PAP 想做的，是让个人 Agent 可以被企业正式识别。

用户决定给 Agent 什么权限。

企业决定这个 Agent 在自己的系统里可以做什么。

需要进入用户账户时，可以通过 OAuth 完成身份和授权；企业又可以通过网站、API 或自己的 Agent 与 Personal Agent 交互。未来 PAP 还准备扩展支付能力。

这里真正发生的是：

“代理”开始从一个软件能力，变成一种可以被外部组织承认的关系。

过去企业只认识：

这个人。

这个账号。

这个 App。

未来它还需要认识：

这是这个人的 Agent，它代表谁，拥有多少权限，这次来想完成什么。

这就是委托代理网络真正开始出现的地方。

## 八、于是商业世界需要一套新的协议栈

如果把未来的一次 Agent 交易拆开，会发现它至少包含几个环节：

Intent

用户想完成什么。

↓

Identity

这个用户是谁。

↓

Delegation

这个 Agent 是否真的代表他。

↓

Authority

它被允许做到什么程度。

↓

Task Routing

应该调用哪个企业、Agent 或服务商。

↓

Execution

完成实际行动。

↓

Payment

资源如何被授权调用。

↓

Verification

事情究竟有没有真的完成。

↓

Settlement / Outcome

各方如何确认结果并完成收费。

过去这些能力散落在不同系统里。

现在开始有人分别试图把它们标准化。

PAP 更接近：

代理身份、授权和企业交互层。

而 Stripe 正在迅速向下面的：

支付和经济执行层

占位。

## 九、这也是为什么我越来越关注 Stripe

Stripe 最有意思的地方，并不是它又多了一种 AI 支付方式。

而是它正在试图成为：

Agent 经济里的资源调用基础设施。

过去 Stripe 的核心作用，是帮助互联网企业收钱。

现在它正在做几件新的事情。

它和 OpenAI 推进 Agentic Commerce Protocol，让 Agent 与商家的商业流程能够程序化交互。

它与 Tempo 推出了 Machine Payments Protocol，让 Agent 可以直接为 API、数据或其他机器服务付款。

它推出 Shared Payment Tokens，让 Agent 可以在用户允许的商家、金额和时间范围内付款，而不需要接触真实支付凭证。

它又给 Link 加上 Agent Wallet，让 Personal Agent 可以代表用户购买东西，同时让用户保留消费控制和可见性。

这些东西单独看都是支付产品。

合在一起看，就不太一样了。

它们正在共同回答：

一个 Agent 获得委托以后，怎样安全地调用用户的经济资源？

这正是我们此前讨论金融时那句话：

支付不是简单的钱从 A 到 B。

支付其实是：

资源配置意图经过授权以后，被现实执行出来。

## 十、因此 Stripe 的位置可能比“AI 支付公司”更深

Personal Agent 不一定自己拥有商品。

也不一定自己拥有企业服务。

它负责路由任务。

Stripe 也不需要拥有 Personal Agent。

它负责：

路由价值。

于是未来可能形成一种很有意思的分工：

Personal Agent：理解我要什么。

PAP：告诉企业这个 Agent 代表谁、被授权做什么。

企业 Agent：提供具体商品和服务。

Stripe：完成支付、资源调用和结算。

如果这套结构成立，Stripe 的位置就有点类似过去支付网络的位置。

Visa 不需要拥有商店。

也不需要拥有消费者入口。

但大量经济活动都会经过它。

Stripe 未来同样不一定要拥有最强的 Personal Agent。

只要大量 Agent 在真正完成任务时，都选择通过它：

授权。

付款。

结算。

退款。

确认经济结果。

它就可能成为：

委托代理网络的经济接口。

## 十一、而真正成熟的商业闭环，还必须解决一个容易被忽略的问题：任务有没有真的完成

前几天看到一个很典型的 Personal Agent 失败案例。

用户让 Agent 为孩子的生日会订贝果。

信用卡支付失败。

真正的问题并不是支付失败。

任何人类助理都会遇到类似问题。

真正的问题是：

Agent 没有告诉用户。

等用户到了店门口，才发现订单从来没有成立。

这个例子非常小，却点出了 Agent Commerce 最困难的一层。

如果 AI 替我办事以后，我还必须自己：

重新确认订单。

打电话给商家。

检查支付。

检查物流。

那它实际上没有真正替我省下多少心力。

所以任务路由真正成立，不是：

Action。

而是：

Action + Verification + Recovery。

Agent 必须知道：

订单发出了吗？

支付成功了吗？

商家确认了吗？

服务能够按时交付吗？

如果失败，有没有重新尝试？

什么时候应该通知本人？

这也意味着真正的 Success Fee 必须建立在：

可验证结果

之上。

“我尝试了”不是结果。

“事情确实完成了”才是结果。

## 十二、所以未来的平台竞争，可能从“流量入口”变成“任务入口”

到这里，可以重新看过去互联网最重要的几个入口。

搜索时代争的是：

谁拥有信息入口。

平台时代争的是：

谁拥有交易入口。

Personal Agent 时代可能争的是：

谁拥有任务入口。

谁能够成为用户第一句话的接收者：

“帮我把这件事情办了。”

然后把这个模糊目标变成：

明确任务。

找到供应商。

决定路径。

调用资源。

完成支付。

验证结果。

只有到了这里，Agent 才真正从一个工具变成代理。

## 十三、从商业观察角度，接下来真正值得盯的是三种新的权力

第一种是：

任务路由权。

谁决定一件需求最终流向哪家企业、哪个服务商、哪个垂直 Agent。

它很可能是过去“流量分发权”的下一代形态。

第二种是：

代理授权权。

谁掌握用户身份、长期 Context 和持续授权。

这决定了谁真正有资格代表用户行动。

第三种是：

资源调用权。

谁能够安全地把代理意图转化成支付、资金和现实资源配置。

这正是 Stripe 这样的金融基础设施可能占据的位置。

如果一家公司同时接近其中两到三层，它的战略价值就可能远高于单纯的 AI 应用。

## 十四、Success Fee 可能只是表面，真正变化的是“责任开始转移”

所以我觉得，“按结果付费”虽然很可能成为 Agent 时代的重要商业模式，但它其实只是表面。

真正发生在底下的是：

完成任务的责任，开始从用户转移到 Agent。

过去软件公司说：

我给你工具。

事情做得怎么样，是你的责任。

未来 Agent 公司可能说：

把事情交给我。

更成熟的时候甚至会说：

做成以后，再付我钱。

一旦走到这一步，它就不再只是软件行业。

它开始同时具有：

软件、

服务业、

代理业、

平台，

甚至金融中介的一些特征。

这可能也是为什么 Agent 时代会产生一些我们过去很难分类的新公司。

## 十五、真正的新平台，也许不是让你“来这里消费”，而是让你“不需要再管”

过去互联网最好的产品，是让一件事情更容易。

更容易找到。

更容易比较。

更容易购买。

Agent 时代最好的产品可能进一步：

让这件事情从你的注意力里消失。

你不需要再想：

在哪里买。

和谁联系。

用哪个 App。

怎么付款。

出了问题找谁。

你只需要说：

我要什么。

然后等待一个可靠的结果。

从这个意义上说，下一代平台真正竞争的已经不是：

“谁拥有最多流量？”

而是：

谁能够在一个越来越复杂的世界里，长期、稳定、可信地替用户把事情办完。

当这个能力成熟以后，互联网最重要的一条商业链，也许会从：

流量 → 广告 → 交易

逐渐增加另一条：

意图 → 任务 → 执行 → 结果 → Success Fee。

而 Personal Agent、PAP、Stripe 这些今天看起来分散的产品和协议，正在一点一点把这条新链路搭出来。

所以今天真正值得观察的，也许不是又多了几个 AI 产品。

而是互联网最底层的一种分配机制开始改变：

过去平台分配的是人的注意力。

未来平台可能开始分配的是：

人的任务、授权和资源。
