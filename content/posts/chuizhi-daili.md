最近在实际体验一些 Personal Agent 产品时，我有一点感受，这个领域的发展也许不会像很多人想象的那样：

突然出现一个无所不能的超级 AI，把我们的数字生活全部接管。

更现实的路径，很可能恰恰相反。

它会先从非常具体、非常垂直的地方长出来。

金融。

健康。

工作。

旅行。

消费。

每个领域先出现自己的连接器、自己的专业代理、自己的授权体系。

随着这些代理越来越多，新的复杂性又会重新出现。

身份重复。

权限分散。

Context 割裂。

不同 Agent 相互冲突。

最终，市场会重新要求一个更高层的统一入口，把这些碎片重新组织起来。

所以 Personal Agent 真正的演化，可能不是：

一个产品不断变强。

而是：

身份、Context、权限和行动能力，从碎片化逐渐走向统一。

而最近开始出现的另一个变化，让这条路径变得更加清楚：

Auth，也就是身份认证，可能成为整个委托代理体系最底层的入口。

## 一、Personal Agent 的第一步，可能不是“替你做”，而是“先知道你是谁”

我们过去使用互联网服务时，很少意识到登录本身也是一种基础设施。

很多网站都支持：

Continue with Google。

表面上，它只是让用户少注册一个账号。

但从更深一层看，Google 实际承担的是一个数字身份锚点：

由它证明，这个网站面前的人还是同一个人。

这件事情看起来简单，却极其重要。

因为只有先确定“你是谁”，后面的数据、权限、历史和授权才有归属。

到了 Agent 时代，这个问题会变得更重要。

因为一个 Agent 需要知道的不只是：

这个账号是谁。

还要逐渐知道：

哪些 Context 属于这个人。

哪些应用可以访问。

哪些资源可以调用。

哪些行动获得过授权。

这些授权什么时候失效。

所以 Personal Agent 真正需要的底层结构，可能不是模型。

而是：

Identity——身份。

身份确认以后，才有后面的代理关系。

## 二、Auth 很可能从“证明我是谁”继续向“谁可以代表我”演化

这也是为什么最近看到 Sign in with ChatGPT 这类产品形态时，我觉得它真正值得关注的地方，并不只是开发者可以降低模型调用和 Token 成本。

更深的意义可能在于：

AI 平台开始尝试成为新的身份入口。

传统 Auth 主要回答：

我是谁？

Agent 时代的 Auth 最终可能继续向下回答：

我允许谁读取什么？
谁可以调用哪些能力？
哪个 Agent 可以代表我完成什么事情？

这里其实包含三个逐渐加深的层次：

Authentication：确认你是谁。

Authorization：确认你允许什么。

Delegation：确认谁可以在什么边界内代表你行动。

最后这一层，才真正进入委托代理。

所以 Auth 在未来可能不再只是一个登录按钮。

它可能逐渐成为：

委托代理关系的根节点。
## 三、身份确定以后，最早出现的仍然会是垂直连接

今天一个人的数字生活，本身就是碎片化的。

金融信息在银行、券商、信用卡、支付和保险里。

健康数据在医院、体检、睡眠、运动、药物和可穿戴设备里。

工作信息散在邮箱、日历、文档、会议、Slack、CRM、ERP 和项目管理系统里。

旅行、购物、学习、家庭也分别生活在不同 App 里。

所以对一个 Personal Agent 来说，最早的问题甚至不是：

“我能替这个人做什么？”

而是：

我能不能先看见这个人在某个领域里的完整状态？

这就是为什么早期 Personal Agent 很可能首先表现为一种：

垂直连接层。

金融 Agent 去连接银行、券商、支付、保险、账单和财务软件。

健康 Agent 去连接医疗记录、运动、睡眠、体检、药物和预约。

工作 Agent 去连接邮件、日历、文件、会议和企业系统。

这一阶段最重要的能力，还不是智能判断。

而是：

把原本割裂的账户、数据、工具和服务重新连接起来。

先把局部世界拼起来。

然后才能真正理解。

## 四、连接完成以后，会自然出现大量“垂直代理”

过去我把这一阶段称为“微 Agent”。

这个词很形象，因为未来很可能真的会同时出现大量碎片化的小型代理。

但如果给它一个更稳定的名字，我更愿意叫：

垂直代理。

它们只负责一个领域，甚至只负责其中一个窄任务。

金融不会只有一个金融 Agent。

它可能继续分成：

现金管理代理。

账单代理。

投资代理。

保险代理。

税务代理。

健康也一样：

睡眠代理。

营养代理。

运动代理。

医疗预约代理。

工作场景会更加细分：

销售代理。

采购代理。

财务代理。

研发代理。

客服代理。

这些垂直代理的共同特点是：

它们不试图理解一个人的全部生活，而是在一个明确边界内取得越来越深的专业能力和行动权限。

这其实很符合委托关系真实的发展方式。

因为人通常不会一开始就把全部生活交给一个系统。

委托总是从：

风险较低、

边界清楚、

规则明确、

结果容易验证的地方开始。

帮我整理账单。

帮我安排会议。

帮我取消长期不用的订阅。

帮公司处理低金额采购。

这些事情做得越稳定，人就越愿意增加授权。

所以 Personal Agent 的中间形态，很可能不是一个超级 AI。

而是：

一个人周围同时存在大量垂直代理。
## 五、垂直代理越多，新的摩擦就越快出现

但如果真的走到这一步，问题也会重新出现。

为什么金融代理、旅行代理和健康代理都要重新确认我是谁？

为什么每一个 Agent 都保存一套自己的偏好？

为什么它们都要分别连接日历、邮箱、支付和联系人？

为什么同样的权限要配置很多遍？

为什么金融代理不知道旅行代理已经为下个月安排了一笔大额支出？

为什么健康代理安排体检时，不知道工作代理已经把那天排满？

更麻烦的是：

如果两个 Agent 的目标发生冲突，谁优先？

旅行代理认为应该订一趟昂贵旅行。

金融代理认为现金流偏紧。

健康代理又认为那段时间最适合安排治疗。

这里真正出现的问题已经不再是：

Agent 不够聪明。

而是：

不同 Agent 无法共同代表一个完整的人。

所以碎片化本身会再次成为新的摩擦来源。

而新的抽象层一定会由此产生。

## 六、于是“代理编排层”会出现

这一层可能是 Personal Agent 真正开始发生质变的地方。

未来最重要的 Personal Agent，不一定什么事情都自己做。

它更像一个：

Agent Orchestrator——代理编排器。

它负责：

理解用户整体目标。

判断应该调用哪个垂直代理。

分配任务。

协调多个 Agent。

解决目标冲突。

保存长期 Context。

统一身份。

统一权限。

决定什么可以自动执行。

什么必须重新交还给人。

这时结构可能逐渐变成：

人

↓

主 Personal Agent

↓

垂直代理

↓

各类 App、账户与现实服务。

到了这一层以后，Personal Agent 就不再只是一个 App。

它开始接近：

个人数字世界的控制层。
## 七、而 Auth 会成为这个控制层真正的底座

这时候再回过来看身份，就会发现它的重要性进一步上升。

如果未来一个人拥有：

金融代理。

健康代理。

旅行代理。

工作代理。

消费代理。

最糟糕的情况就是：

五套身份。

五套权限。

五套长期记忆。

五套授权管理。

五套撤销机制。

用户不会长期接受这种复杂度。

所以一定会出现一个更统一的身份与授权层。

它至少要回答：

Identity

这些 Agent 都代表同一个人。

Context Boundary

健康代理能看到什么。

金融代理不能看到什么。

Authority

哪个 Agent 有什么权限。

Delegation

哪些事情可以持续代办。

Revocation

怎样一键取消代理资格。

Audit

过去一个月，它代表我做过什么。

走到这一步以后，Auth 已经不再是传统意义上的登录系统。

它开始接近：

Delegation OS——委托代理操作系统。
## 八、最终市场可能不会留下几十个一级入口

如果沿着这条路径继续向前，我不太相信普通用户最终会长期维护几十个一级 Agent。

复杂性最终一定会被重新封装。

大量垂直代理会继续存在。

但它们会逐渐退到后台。

前台可能只剩少数几个大型 Personal Agent 或委托代理入口。

它们统一管理：

身份。

Context。

记忆。

权限。

支付。

资源调用。

Agent 编排。

底下再连接不同垂直 Agent、企业、平台和现实服务。

于是结构会逐渐从：

人 → 很多 Agent → 很多 App

收敛成：

人→ 少数主代理→ 大量垂直代理→ 外部世界。

真正重要的问题也会发生改变。

不再是：

哪个 Agent 会做的事情最多。

而是：

谁成为默认代理接口。

## 九、这和超级 App 很像，但比超级 App 更深

超级 App 的逻辑是：

把很多服务装进同一个入口。

支付。

打车。

购物。

金融。

社交。

但 Personal Agent 更进一步。

它不要求所有服务必须“住进来”。

它真正争夺的是：

所有服务通过谁来理解和服务这个人。

超级 App 仍然是：

人主动找到服务。

Personal Agent 则可能逐渐变成：

服务先通过代理理解人的需求，再来到人面前。

所以它争夺的不只是流量入口。

而是：

关系入口。

过去互联网争的是：

用户先打开哪个 App。

未来 Agent 争的可能是：

谁最先知道用户为什么要行动，并决定应该调用哪个服务。

这是一个比流量更深的位置。

## 十、所以 Personal Agent 真正的护城河可能有六层

过去我们把 Personal Agent 的核心能力概括成：

Context。

Distribution。

Action。

Authority。

Orchestration。

现在还需要在最下面加一个：

Identity。

于是完整结构变成：

Identity→ Context→ Distribution→ Action→ Authority→ Orchestration

Identity：

它能不能成为你的稳定数字身份锚点。

Context：

它到底理解你多深。

Distribution：

它是不是每天都能够触达你。

Action：

它能不能真正完成事务。

Authority：

你愿不愿意让它代表你行动。

Orchestration：

它能不能协调其他 Agent 与服务共同完成目标。

这些能力不是简单相加。

更像相乘。

有 Context，没有 Action，只是一个懂你的聊天机器人。

有 Action，没有 Authority，只能不断请求确认。

有 Authority，没有统一身份和编排，又会重新陷入碎片化。

真正强的平台，是这些结构同时开始沉积。

## 十一、这里可能出现一种新的“纵向网络效应”

传统互联网平台最典型的网络效应是横向的。

用户越多，平台越有价值。

商家越多，消费者越愿意来。

消费者越多，又吸引更多商家。

Personal Agent 可能增加另一种非常特别的网络效应：

同一个用户和它相处越久，这段关系本身越有价值。

使用一年以后，它知道你的历史。

使用三年以后，它知道你的偏好。

再往后，它可能开始知道：

哪些事情你通常接受。

哪些事情你一定拒绝。

什么目标对你更重要。

哪些资源可以被调用。

哪些行为可以自动执行。

这时最难迁移的已经不是模型。

甚至不只是数据。

而是：

长期沉积下来的身份、Context、权限和行动历史所组成的关系结构。

时间本身开始成为护城河。

这就是一种：

纵向关系复利。

## 十二、所以 Sign in with ChatGPT 这类 Auth 的真正意义，可能比登录本身更深

如果越来越多第三方应用开始接受某个 AI 平台的身份，那么发生的就不仅是：

这个平台获得更多登录用户。

而是：

越来越多外部 Agent 开始围绕同一个身份建立关系。

这会产生一种很重要的力量：

Identity Gravity——身份引力。

Google 曾经建立过这种引力。

Apple 也有。

Microsoft 在企业世界里同样拥有很强的身份基础。

现在大型 AI 平台开始有机会进入这一层。

一旦身份、Context、模型能力、外部工具连接和授权体系逐渐汇聚，一个平台就可能从：

AI 服务提供者

走向：

Agent Identity Layer。

它不一定亲自做所有垂直 Agent。

但大量垂直 Agent 都围绕它的身份、权限和智能能力生长。

这可能比自己做一百个应用更加重要。

## 十三、对创业公司而言，这反而可能重新打开机会

这并不意味着最后所有机会都会被大型平台拿走。

恰恰相反。

如果模型、身份认证、插件、MCP、云计算逐渐变成基础设施，创业公司就不必从头解决所有问题。

它们可以更专注于：

理解某一个垂直领域里的代理关系到底应该怎样设计。

金融怎么授权。

健康怎么授权。

法律怎么授权。

采购怎么授权。

哪些事情可以自动做。

哪些事情必须交还给人。

真正的竞争会逐渐从：

“谁有更强的模型”

变成：

“谁最懂这个领域应该如何被代理。”

所以垂直代理并不会消失。

相反，它们可能越来越繁荣。

只是其中的大多数最终会生活在更大的身份与代理平台之上。

## 十四、从投资角度，真正应该观察的是三种集中

如果这条产业路径成立，那么未来最值得跟踪的已经不只是下载量和模型 benchmark。

而是：

Context 正在向谁集中？

谁越来越了解一个人或者一家企业。

Authority 正在向谁集中？

用户愿意把越来越多行动权交给谁。

Identity 正在向谁集中？

越来越多第三方愿意接受谁来证明：

“这个人是谁，以及他授权了什么。”

如果这三者开始同时向一个平台聚集，

再加上 Action 与 Orchestration，

它就可能不再是普通的 AI 产品。

而是在形成：

委托代理基础设施。
## 十五、真正的终局也许不是一个超级 AI，而是一张个人代理网络

所以我现在反而不太喜欢“超级 Agent”这个说法。

它容易让人想象：

一个 AI 什么都会。

更现实的形态可能是：

一个主 Personal Agent 理解你。

下面连接很多垂直代理。

金融代理管理资源。

健康代理管理健康。

工作代理管理工作。

旅行代理管理出行。

消费代理管理消费。

这些代理拥有不同权限。

彼此协调。

而在它们最下面，还有统一的身份和授权根节点。

最终由主代理理解：

这个人究竟想要什么。

这样一来，Personal Agent 就不再只是一个软件。

它开始成为：

一个人的数字关系结构。

而整个演化过程可能是：

统一身份→ 垂直连接→ 垂直代理→ 权限与 Context 沉积→ Agent 编排→ 大型委托代理入口。

这条路不会一夜完成。

中间一定会有大量竞争、分叉、封闭生态和失败产品。

但方向已经越来越容易辨认。

Personal Agent 最开始解决的是：

AI 如何理解一个人。

垂直代理解决的是：

不同专业领域如何获得行动能力。

Auth 解决的是：

这些代理究竟代表谁。

Authority 解决的是：

它们被允许做到什么程度。

Orchestration 最终解决的是：

所有这些碎片，如何重新组成一个完整的人。

所以未来 Personal Agent 真正争夺的，可能不是：

谁最聪明。

甚至也不只是：

谁最懂你。

而是：

谁能够成为你在数字世界里的身份根节点，并获得持续代表你与世界发生关系的资格。
