这几天连续发生了两件事。

单独看，都可以归进“金融安全新闻”。

放在一起看，却有点不一样。

第一件发生在美国。

10 月 22 日，Axios 报道，摩根士丹利、摩根大通、美银、富国、花旗等大型银行，最近陆续在客户账户里发现了一种过去很少见的访问者：

*第三方 AI Agent。*

它们不是传统黑客。

很多时候，用户名是真的，密码是真的，甚至连允许它进入账户这件事，也是用户自己做的。

有人把自己的网银凭证交给 Personal Agent，让它查账单、分析现金流、管理财务。

问题出在后面。

银行发现，它们很难判断 Agent 的某一个具体动作，究竟是用户明确要求它做的，还是 Agent 为了完成一个更宽泛的目标，自己继续往前推演出来的动作。

Axios 的信源甚至提到，一些 Agent 看起来出现了超出用户原始指令的行为。摩根士丹利已经开始封堵第三方 Agent；其他大型银行也在限制访问，比较现实的中间状态，是允许经过许可的系统读取数据，但暂时不允许它们随便移动资金。

网上很快出现了更惊悚的说法：

“AI 已经偷偷进入美国银行账户，自己开始转账。”

目前并没有足够证据支持这种版本。

Reuters 后续确认了大型银行确实正在封锁第三方 Agent，但也特别指出，所谓 Agent 已经出现“自主越权行为”的具体案例，主要来自 Axios 的匿名信源；摩根士丹利自己则表示，没有发现所谓失控 Agent 进入其平台。

可真正值得注意的，本来就不是“AI 有没有已经偷走一笔钱”。

而是另一件事：

**这些 Agent 很多不是偷钥匙进去的。**

**钥匙，是主人自己给它的。**

几乎同一时间，日本发生了另一件事。

这一次，连钥匙都没用了。

10 月 14 日，日本岩井コスモ证券发现，委托运营其互联网交易系统的 Trade Works 遭到非法访问。

随后确认，攻击不只造成了信息泄露。

攻击者还触及了证券公司的交易管理系统。

7 个客户账户出现了本人从未下达的买卖指令，其中 5 个账户真的完成了成交。

4,975 名客户的姓名、邮箱等信息一度处于攻击者可访问状态。

更特别的是，公司明确表示，这些异常交易并不是因为客户密码被偷。

交易密码没有泄露。

客户登录本身还有多因素认证和 Passkey。

Trade Works 后来的说明是，正常的用户登录路径原本已经有多重认证保护，但系统部分管理功能存在配置缺陷，被攻击者利用了。

岩井コスモ证券后来又公开表示，攻击者使用 AI 探测系统弱点并发起攻击。公司没有披露具体使用了什么模型，也没有证据证明这是一个自主 AI Agent 独立完成了整条攻击链，所以不能把它描述成“AI 自己攻破了证券公司”。

但有一点非常清楚：

**客户自己没有下单。**

**客户身份认证也没有被突破。**

**交易却真的发生了。**

两件事放在一起，事情就开始变得有意思了。

## 一

美国银行碰到的问题，是：

**一个合法进入账户的代理，会不会多做一步。**

日本证券公司碰到的问题，则是：

**攻击者能不能绕开用户这一层，直接拿走后台的执行权。**

表面完全不同。

一个发生在用户授权端。

一个发生在系统控制端。

可最后碰到的是同一个问题：

> **一笔金融行为，到底怎样才能被证明是“这个人真正授权发生的”？**

过去我们很少把这个问题拆得这么细。

银行、券商花了几十年解决身份认证。

用户名。

密码。

短信验证码。

设备。

人脸。

指纹。

Passkey。

所有这些东西都在回答：

**这是不是真的你？**

可现在突然发现，证明“这是你”，还远远不够。

## 二

假设我有一个 Personal Agent。

它用了半年，帮我整理邮件、管理订阅、安排旅行，我越来越信任它。

于是某一天，我把银行账户也接了进去。

我告诉它：

“帮我看看最近现金流有没有什么可以优化的地方。”

我心里的意思可能只是：

看看。

分析。

告诉我。

Agent 却可能理解成：

既然要优化现金流，那么这笔闲钱是不是应该转走？

那边收益是不是更高？

是不是应该自动调整？

如果它真的多走了一步，银行看到的仍然可能是一套完全正确的身份凭证。

用户也确实授权这个 Agent 进入过账户。

可用户会说：

**“我没有让它做这笔交易。”**

这时候问题已经不是身份真假了。

而是权利边界。

过去常常被揉成一件事的几个问题，现在必须被拆开：

**这是谁？**

**谁可以代表他？**

**这个代理到底能做什么？**

**这一笔具体操作，是不是符合本人真实意图？**

而日本那件事又把问题往后推了一层：

即使前面这些都对，

**从授权到最终成交的整条执行链，有没有被人从中间改掉？**

于是金融系统真正需要守住的东西，开始从一个登录入口，变成一整条链：

身份。

代理资格。

授权范围。

真实意图。

系统完整性。

执行。

结果确认。

最后还有责任。

听起来很复杂。

但钱一旦真的可以被机器调动，这些问题一个也绕不过去。

## 三

这也让我重新理解“账户”。

我们平常把银行账户想象成一个钱袋。

里面有多少钱。

今天进多少。

明天转多少。

可企业财务从来不会这样理解账户。

公司账户真正重要的是：

谁能看。

谁能付。

谁能审批。

一笔最多多少。

什么用途能付。

哪些供应商能付。

超过哪个金额要找谁。

换句话说，一个账户从来不只是资源的容器。

它本来就是：

**资源加权利。**

过去，权利主要分配给人。

老板。

财务。

基金经理。

受托人。

家属。

以后要多一个新的角色：

**Agent。**

问题也就变成：

它能看什么？

能动什么？

一天能动多少？

能不能增加新的收款人？

能不能买证券？

这次授权持续多久？

什么时候必须回来再问一次？

真正适合 Agent 的金融账户，不会是“把网银密码给它”。

那太粗糙了。

它更像企业里的权限体系：

你有这个角色。

拥有这部分权限。

超出边界，必须升级。

## 四

所以美国银行现在先退回“只读”，其实很正常。

这不是 Agent 金融被打回去了。

更像一种自然的试探。

先让机器看。

然后分析。

再让它准备动作。

由人确认。

跑得足够久以后，再开放一些低风险、边界清楚的小额权限。

最后可能才出现：

“这类事情，以后你自己处理。”

金融的速度一定会比订酒店慢。

因为钱太硬。

酒店订错了，还能退。

如果 Agent 多转了一百万，第二天讨论的就不是用户体验。

是责任。

这也解释了为什么金融很可能成为最早把 Agent 权利结构真正逼成熟的行业之一。

不是因为银行愿意创新。

而是因为它没有不把这个问题想清楚的余地。

## 五

但日本的事情又提醒我们：

把 Agent 权限设计好，还不够。

岩井コスモ证券这次真正让人不舒服的地方就在这里。

客户侧已经有 MFA 和 Passkey。

如果把安全全部理解成“如何确认客户本人”，这些措施没有什么问题。

可攻击者没有从那扇门进。

他碰的是后台。

当后台管理控制面被利用以后，系统完全可以在客户没有操作的情况下产生一笔真实订单。

这意味着未来金融安全还必须多守一层：

**执行链本身必须可信。**

一笔交易不能只是：

系统里出现了这条指令。

还得知道：

谁生成的。

谁授权的。

经过哪些系统。

中间有没有被修改。

哪一个程序执行。

最终发生了什么。

这就已经不只是传统意义上的账户安全。

而接近一种：

**全链路的权利证明。**

## 六

到这里，最近一两个月看起来有些零散的行业动作，也就慢慢能拼起来了。

Sierra 在推 Personal Agent Protocol。

它想回答：

这个 Agent 代表谁，企业应该允许它做什么。

Stripe 在做 Agent Wallet、受限支付、人工审批、资金操作和结果状态。

它想回答：

当 Agent 获得合法授权以后，钱怎么安全地动。

Visa 在推 Trusted Agent 一类的身份与支付机制。

1Password 试图让 Agent 可以使用账户凭证，但又不真正看到用户密码。

网络安全公司开始研究 Agent 的运行时权限、行为监控、越权拦截和审计。

它们看上去分别属于：

AI。

支付。

身份。

安全。

其实都在围绕同一个新的基础设施问题生长：

> **机器如何正式获得一部分属于人的行动权，同时又不能把这部分权力变成一张无限制的通行证。**

## 七

所以这次两件金融事件之后，我觉得此前说的 Delegation Infrastructure——委托基础设施，还要再加一层。

过去我更关注：

身份。

授权。

额度。

审计。

现在还要加上：

**Integrity——完整性。**

也就是：

即使授权本身没有问题，也要保证从授权到最终执行的链条没有被替换、篡改或者劫持。

于是未来可能真正值钱的基础设施，不只是“证明这个 Agent 是谁”。

而是：

> **证明这条行动从人的意图出发，一直到最终成交，始终没有偏离允许的边界。**

这里面可能包括：

代理身份。

细粒度权限。

交易指令签名。

运行环境隔离。

异常行为检测。

不可篡改日志。

执行结果回执。

责任审计。

听上去很像今天的金融安全。

但区别在于：

以后系统里的行动主体不再只有人和固定程序。

*还会多出大量会规划、会调用工具、会自己寻找路径的 Agent。*

## 八

投资上，这可能会形成一个很容易被忽略的新利润池。

过去 AI 投资最直接的基础设施是：

GPU。

HBM。

数据中心。

网络。

存储。

Agent 真正开始进入现实系统以后，还会长出另一套基础设施：

**Identity + Delegation + Runtime Security + Audit。**

它们不像 GPU 那样有一个显眼的物理短缺。

它们的稀缺性来自另一种东西：

**可信。**

银行不会为了便宜 20%，随便更换管理全部 Agent 授权记录的系统。

企业也不会轻易迁移几年积累下来的：

代理身份。

权限规则。

审批记录。

风险模型。

责任日志。

一旦这些东西真正进入生产系统，切换成本很可能非常高。

这就是它可能变成基础设施生意的地方。

## 九

而银行本身也可能因此发生变化。

过去一家银行账户主要证明：

**这些钱属于你。**

Agent 时代，一个更完整的账户可能还要表达：

**哪些代理可以在什么条件下代表你使用这些钱。**

这会逐渐变成新的产品能力。

未来可能有一家银行只能做到：

Agent 能读余额。

另一家银行已经做到：

固定账单可以自动付。

老收款人每天五千以内自动执行。

新收款人必须本人确认。

投资交易不能做。

所有 Agent 操作都有独立记录。

发现异常，一键撤权。

那用户愿意把 Personal Agent 接到哪里？

答案并不难想。

所以未来银行争的不只是存款、信用卡、支付体验。

还可能争一个新的东西：

> **谁拥有最好用、最可信的 Agent 权限体系。**

## 十

然后就是最麻烦的问题。

钱出了问题，谁赔？

美国这次案例里，如果客户自己把银行密码交给 Agent，后来 Agent 真的做了一笔超出用户意图的交易，这笔交易到底算不算“未经授权”？

并没有那么容易回答。

Reuters 特别提到，正因为客户可能主动分享过凭证，传统的“unauthorized transaction”概念会变得复杂。

日本那边又是另一种情况。

客户什么都没做。

后台被攻破。

交易却发生了。

这里的责任链相对清楚一些，但也说明供应商、运维方、券商、交易系统之间的责任必须被重新审视。

到了 Agent 真正大规模进入金融以后，责任还会继续往更多主体扩散：

用户。

Agent 公司。

模型公司。

银行。

支付网络。

第三方工具。

云平台。

以后甚至可能还要有新的保险。

很多制度，最后都不是技术人员设计出来的。

而是事故逼出来的。

汽车有了以后，才慢慢有驾照、交通法和车险。

Agent 真正开始动钱以后，大概也一样。

## 十一

所以我不太把这两件事理解成“金融系统开始抵制 AI”。

我更愿意把它理解成：

**委托代理第一次真正撞上了财产权。**

以前 Agent 做错一件事，最多是：

邮件写错。

酒店订错。

文件删错。

到了金融这里，它面对的是所有权和控制权。

谁有资格动我的钱？

为什么能动？

动到哪里？

谁负责？

这些问题一旦开始被认真回答，Agent 才真正从一个好玩的产品，进入社会制度。

也只有到了这里，“委托代理”这四个字才真正有重量。

## 十二

我们之前一直在用一条很简单的线理解 AI：

互联网是：

**Find——帮我找到。**

Agent 开始变成：

**Do——帮我完成。**

再往前：

**Delegate——代表我持续去做。**

后来因为 Instinct 那次支付失败却没有通知用户的案例，我们又补了一个：

**Verify——必须知道事情到底做成没有。**

现在美国银行和日本证券这两件事之后，还应该再加两个词：

**Govern。**

你必须被权利边界约束。

以及：

**Integrity。**

从你的意图到最终结果，整条执行链必须可信。

于是这条路越来越完整：

> **Find → Do → Verify → Delegate → Govern → Integrity。**

越往后，越不像一个 AI 产品问题。

越像一个新的社会基础设施问题。

这几天发生的事情，也许还只是一些很小的裂缝。

美国大行先把门关小一点。

日本证券公司先把后台漏洞堵住。

下一步会出现新的协议。

新的授权系统。

新的 Agent 身份。

新的审计。

新的责任规则。

一点一点补上去。

很多年以后再回头看，也许真正重要的不是哪一次攻击、哪一家银行封了哪个 Agent。

而是从这一刻开始，金融体系第一次认真面对了一个过去不存在的问题：

> **如果机器也可以代表人行动，那么财产权到底应该怎样被机器安全地代理。**

这个问题一旦有了答案，才会真正打开 Agent 进入现实经济的门。
